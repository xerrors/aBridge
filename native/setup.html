安装与修复 aBridge

运行时与 Cua Driver

在“设置 → 运行环境”点击“安装 / 修复”。这会使用锁定依赖和哈希校验修复当前用户的 Python 环境，不需要另装 Cua App 或本地模型。

若提示缺少 uv，先按uv 安装说明安装，再重开 aBridge。若安装文件不完整，在内部项目源目录运行：

python3 deploy/install_client.py
open "$HOME/Applications/aBridge.app"

系统权限

分别点击“屏幕录制”和“辅助功能”旁的“前往设置”，允许实际安装的 aBridge。原生更新后，macOS 可能要求重新允许；按系统提示退出并重开客户端。

浏览器

安装Google Chrome。启用本机“浏览器”能力，并在管理台明确给 Agent 增加浏览器授权。

首次连接，在该 Chrome Profile 中打开 chrome://inspect/#remote-debugging，开启“Allow remote debugging for this browser instance”。只允许信任的应用连接。

若系统拒绝读取连接信息，点击“允许访问…”，只选择该 Chrome 目录内的 DevToolsActivePort 文件，再接入当前页。授权会在本机保留，文件被替换或授权失效时需重新选择。

在 Chrome 中为任务打开一个窗口，再在 aBridge 刷新并选择该窗口，点击“接入当前页”。Agent 将复用这个窗口的 Profile、Cookie 和登录态，并控制当前标签页；结束会话只断开连接，保留 Chrome 与页面。

“接入当前页”会做一次本机连接准备，可能短暂显示 Chrome。按浏览器提示允许连接后，Agent 的网页操作使用后台模式。

需要空白环境时可显式选择“临时窗口（不复用登录态）”。窗口或进程变更后，重新在本机选择目标。

连接与诊断

设备 Key 保存在当前用户专用的 0700 目录和 0600 文件中，启动及重连不读取钥匙串。已有绑定时留空设备 Key，点击“重试连接”。“重新检查”更新运行环境状态；“查看诊断”打开仅保存在本机的错误日志。

日志、版本、安装、权限和服务连接是不同状态。缺失的能力不会作为可用能力上报。
