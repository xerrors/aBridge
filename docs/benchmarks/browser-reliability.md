# 浏览器工具通用可靠性验证

本轮固定模型与任务 prompt，检查低成功率是否来自工具能力和契约问题。只修跨页面通用问题，不编写 MiniWoB、邮件、航班、日历或具体答案的处理分支。小样本前后对照仍含模型随机性，不能据此宣称模型完全没有影响。

## 已确认的问题类别

| 通用问题                          | 诊断证据（原始与中间迭代）                                                                                             | 实现与独立验证                                                                                                                                                                 |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 可见内容没有可操作引用            | 邮件与树节点共4例，目标在正文但观察只提供根引用；另有可见提交文字没有引用                                              | 在有界 AX 观察中补充 StaticText 引用，交互控件优先、预算和截断提示保留。普通 span/div 点击、自有混合文字与相邻按钮 fixture 验证，与公开任务无关                                |
| DOM 节点类型与输入契约不一致      | 3例对根节点按 Tab 时调用不存在的 `Document.scrollIntoView()`，产品随后关页                                             | 页面按键映射到本页，保留当前键盘焦点；Text 点击使用文字 Range 区域，不使用整个父容器中心。真实 Chrome 验证 Tab 推进焦点、文字点击不会误触旁边按钮                              |
| 已知不可编辑被处理为未知写失败    | 对只读字段 fill 后关页，本可改用页面控件继续操作                                                                       | 观察返回 `read_only`、`input_type`；在 focus/scroll/Input 之前纯验证，已知无效目标明确拒绝并保留会话。真实 Chrome 验证原值不变，随后在同页可编辑字段继续填入成功               |
| 引用寿命与模型往返不匹配          | 原10秒期限在表单、邮件、航班、布局任务中产生重复观察/过期循环                                                          | 共享浏览器期限改为60秒；会话、导航、动作、文档版本、目标与输入几何校验保留。时钟测试验证30秒可操作，61秒拒绝且不发输入；桌面独立120秒期限不变                                  |
| 原生鼠标事件顺序被预先 focus 破坏 | 动态候选在点击前消失；独立弹出选择器 fixture 同样失败：提前 focus 引发 blur，绕过控件用于保持输入焦点的 mousedown 处理 | 点击、悬停不提前 focus，交给原生鼠标事件；滚动使用明确 DOM 语义；fill 在其输入阶段 focus，元素按键仍显式 focus。真实 Chrome 验证独立候选选择成功                               |
| 无文字图标看得见却无法引用        | CSS 图像元素可见且有 pointer 提示，但无文字、ARIA或可聚焦属性，AX观察遗漏                                              | 有界只读 DOM walker补充中性视觉引用和视口矩形，保留原始DOM对象身份；不猜功能、不按旧坐标绑定新元素。独立CSS图标fixture验证正确原生点击，隐藏、装饰和被遮挡图标不作为候选       |
| 当前遮挡被作为未知写错误销毁页面  | 输入前即可确认当前视口目标被覆盖                                                                                       | 在任何scroll/focus/Input前只读检查，明确拒绝后可先关闭覆盖层再继续；真实Chrome验证未输入、页面保留并成功恢复                                                                   |
| 后台标签的滚轮回执不代表实际滚动  | 普通独立长列表重现 result_timeout；并发补帧只得到 wheel=1，但偏移仍0                                                   | 不发滚轮、不做未知结果后的补滚，直接选择最近滚动容器即时 scrollBy 一次，返回实际 delta；真实Chrome隐藏页滚动650、wheel=0。这是DOM语义，不伪称原生滚轮                          |
| 把滚动容器裁切误判为覆盖          | 目标虽然位于页面viewport内，却在内部scrollport外，原前置检查误拒绝，点击与滚动都无法继续                               | 独立嵌套容器复现后，区分裁切与覆盖；仅有最终命中检查的输入允许先滚入视野，真实overlay仍拒绝，select不绕过；DOM scroll无需pointer命中。真实Chrome验证目标自动露出并原生点击成功 |

Text 的 fill/select 会在纯验证阶段拒绝，要求选择具体输入框或下拉控件。真正已经可能产生副作用的输入失败仍按未知结果处理，不重放；没有为提高分数放宽未知写操作的处理。

这不是一套业务做题策略。没有加入某个收件人、字段名、页面 CSS selector、日期、目标答案或点击路径；模型应自行依据当前观察操作。对于仍失败的单一任务流程，保留原结果，不增加专用规则。

## 最终版本的配对结果

最终产品提交 `9a693cb` 完整复跑 seed 0/1，严格成功 **8/12（66.7%）**，原始基线 **5/12（41.7%）**。4例均为180秒预算耗尽，保留在分母中，未把中间版本11/12作为最终成绩。当前没有任务不合规的独立证据，剔除0例；完整指标与额外seed=2结果以[全量报告](cases-all.md)、[标准审核报告](cases-conforming.md)和[图表](miniwob-comparison.svg)为准。

本轮存在评测运行质量干扰：CLI stderr记录的目录刷新超时从stage4的6条增至最终批次19条，多次记录 `failed to refresh available models: request timed out`。同一表单seed0均使用6次工具调用，中间stage4与最终运行的桥接HTTP累计耗时分别约15.503秒、15.480秒，Agent端到端耗时却从76.269秒增至154.515秒。证据支持工具之外存在额外等待，尚不能定量归因于模型目录刷新、模型推理或网络的各自占比。没有修改全局CLI配置、模型、prompt或预算，也没有为抬高成绩重跑失败样本。这些超时是端到端失败，不能作为坏题剔除；该批结果不支持稳定性能或成本优势的结论。

逐例轨迹审核确认：邮件两例在发送前遇到 `stale_observation` 后重新观察，再耗尽预算；航班两例搜索完成后耗尽预算，最后动作可能仍未返回，不能认定其执行成功或失败。两个最终成功的表单案例中仍出现可恢复的覆盖拒绝。由此不能写成“全部工具错误消失”或把四例超时统一归因于模型。网关中未完成调用保存的 `status:0, elapsedMs:0` 仅表示采集时未返回，不代表成功或零耗时。

最终版本的工具改动由独立自有fixture验证：**8组真实Chrome回归通过，266项自动测试通过**。这证明已复现的通用缺陷得到修复，不能替代更大样本或更稳定运行环境的端到端评估。

## 中间版本 stage4 的配对结果

同一批 seed 0/1，严格成功由 **5/12（41.7%）提升到11/12（91.7%）**，本轮 **0剔除**。原成功样本全部保持成功；新增成功来自树节点2例、布局1例、邮件2例、航班1例。任务 prompt 和模型不变，未增加180秒或40次调用预算。

剩余1例为 `time_budget`，按固定180秒预算计失败。任务已正确初始化，没有证据违反任务约定；不能把超时当作坏题剔除。该例用量和最终奖励未知，不记为零、不猜测业务结果。主对照命令正常结束，12/12会话清理通过，无工具越权。

Agent耗时P50为 **62.1秒→75.7秒**，工具调用总数 **70→78**。这次改善可靠性，没有证明端到端更快或更便宜。用量覆盖 **12/12→11/12**，已知输入2520152、其中缓存2233984、已知输出6627；缺失一例用量，不能比较完整总成本，CLI也不提供实际美元账单。

## 中间版本 stage2 的配对结果

同一批 seed 0/1，严格成功由 **5/12（41.7%）提升到9/12（75.0%）**。原成功样本全部保持成功；新增成功来自树节点2例、布局1例、航班1例。任务 prompt 和模型不变，未增加180秒或40次调用预算。

Agent耗时P50为 **62.1秒→93.5秒**，工具调用总数为 **70→63**。这次优化提高了可靠性，没有证明端到端更快。用量覆盖为 **12/12→11/12**；有一例超时缺失 token，当前不能比较完整总成本，CLI也不提供实际美元账单。

有一例已超时，判分请求遇到 `session_busy`：stage2 的12例命令退出码为1，快照保留原始 `setup_or_grading_error`、`timedOut=true` 和未知奖励，不改写成已判分或剔除样本。该例按固定严格预算本已失败，因此9/12不依赖猜测页面最终奖励。随后评测器补充了已超时/超调用预算时跳过抢占判分、直接清理的通用处理；没有重新尝试该例。

额外 seed=2 为 **4/6**，用量与清理覆盖均6/6；不与原12例合并，也不作为大样本泛化结论。

## 验证设计

- **控制变量**：`gpt-6.1-sol` / medium、相同 Codex adapter、相同任务 prompt、任务、seed 0/1、180秒/40次调用、并发2、无重试。MCP 引用有效期描述随实际工具契约从10秒同步为60秒。
- **Prompt 核验**：任务 prompt 字面量与基线提交 `e3dfc04` 逐字一致，SHA-256 为 `2829bb5539547a0ee72767d94e9ddc66fd5459fb2c41a7ffda2432bcde7086d0`；`codex-agent.ts` 与基线逐字一致。
- **泛化检查**：同六类任务额外固定 seed=2，共6例，与原12例分开统计。这是额外种子，不是六种全新任务或严格独立盲测；中间版本也运行过该集合。
- **通用真实浏览器回归**：自有页面覆盖无语义文字、混合容器精确点击、页面根键盘、只读拒绝后同页恢复、弹出选择器的原生鼠标事件顺序、无文字图标、遮挡恢复、后台DOM滚动与嵌套scrollport裁切后的自动露出点击。模型只调用公开工具；点击/按键为原生输入，滚动为明确DOM语义。
- **确定性安全回归**：跨会话、过期、导航失效、未知写不重放、文本定位和前置拒绝均纳入自动测试。

## 证据与解释边界

迭代中发现10秒期限造成跨任务循环，中止了该不完整批次并保留本地轨迹。中间完整版本取得8/12和额外种子4/6，分别保留在 [stage1 配对结果](miniwob-tools-stage1-results.json) 与 [stage1 额外种子](miniwob-tools-stage1-holdout.json)。随后通过独立 fixture 确认通用预先 focus 问题，最终版本重新运行完整集合；不从任何批次抽取最好结果。全部正式失败进入分母，超时缺失用量记未知。工具改动可能提高成功率，也可能增加观察内容、耗时和 token；报告会同时展示资源消耗。

固定模型和任务 prompt 的对照，加上独立 fixture 对工具错误的复现，可支持“存在且修复了通用工具缺陷”；单次小样本变化无法精确分解模型随机性、后端或网络波动，也不能证明优于其他工具。匿名图标、复杂自动补全或站点流程中的剩余失败，不在本轮添加任务专用处理；如后续推进，应先以独立页面复现成可验证的通用能力问题。

图的输入摘要由 `benchmark:report:check` 校验，避免表格更新而图片仍是旧成绩。制图脚本同时生成仓库内 SVG 与忽略目录 `.local/bench/artifacts/benchmark-comparison.png`；默认 CI 不安装 Python，只核验已提交图和数据的一致性。

制图环境可单独安装，不影响产品与 benchmark：`python3 -m venv .local/bench/.venv`，然后 `.local/bench/.venv/bin/pip install matplotlib==3.11.2`，使用 `.local/bench/.venv/bin/python tools/bench-plot.py`。macOS 使用系统 Heiti 字体，Linux 需安装 Noto Sans CJK。

## 两份报告与剔除标准

[全量案例报告](cases-all.md)包含最终固定集合的每次尝试，主对照12例与额外种子6例分别统计。[按任务标准审核后的报告](cases-conforming.md)使用预先写明的[审核政策](../../tools/bench/case-policy.json)，逐项列出剔除原因和独立证据。

允许审核的情形仅为任务源码完整性违反约定、任务未按约定初始化、存在未声明外部前置条件，或任务本身要求声明范围外的操作。失败、超时、模型未完成、工具缺少引用或输入错误都不能作为剔除理由。判分采集故障单独记录，不能据此删除一个已按严格预算失败的样本。

当前没有发现不符合任务约定的 case，剔除清单为空；两份报告分母相同。初始化不合规仅指Agent动作前已确认的错误，不能将操作后的异常状态挪到此类别。无语义图标与动态候选均为可见页面内容，属于需要修复的工具问题，而非坏题。旧日期在上游控件允许范围内，不能仅因使用2016年就排除航班任务。

中间版本 stage3 的全量结果为10/12，保存在[stage3记录](miniwob-tools-stage3-results.json)。其滚动故障随后在无业务逻辑的独立长列表复现，因此继续按通用工具问题修复，没有把航班case剔除。旧数据与故障记录保留；此阶段未运行额外seed=2，不借用其他版本的额外成绩。

stage4 的11/12与额外5/6完整保留。其两例预算耗尽前存在覆盖拒绝，独立审查没有将它们视为坏题；随后用嵌套滚动fixture发现裁切误判并继续修复。因此旧预算失败只保留为该版本实际结果，不声称已经证明其原因纯属模型耗时。

自动测试还出现过一次重连用例的10毫秒固定等待失败并留下未退出进程，原日志保留。测试改为有上限地等待标签页与连接真实状态，并在断言失败时执行解绑清理；原顺序断言保留，没有删除或放宽产品要求。
