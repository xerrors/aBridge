# 前端实现与界面约定

适用于 `apps/web/`。遵循根目录约定；视觉与资产以 [设计规范](../../docs/design.md) 为依据，验证范围参考 [贡献指南](../../.github/CONTRIBUTING.md#修改与验证)。

## 产品与视觉

- aBridge 与 AI 家共用 `/admin` 管理后台，在现有导航和模块中扩展功能，不另建一套管理台。
- `/admin` 所有模块固定参考设计规范中指定的 Materio Free 版本。沿用已确认的左侧插画、右侧表单登录布局及紫色标记；桌面工作区使用左侧图标导航、紫色渐变选中项和统一的表面、间距、字体与操作样式。
- 后台视觉规则只作用于管理后台。其他产品界面继续遵循各自品牌和设计规范，品牌资源复用已有单源，不自行重画或替换。
- 页面标题与操作对齐，沿用设备页的标题栏结构：一个刷新图标，按需提供一个明确的主操作。复用 `RefreshButton`，不在标题栏和内容区重复刷新、标题或同一操作。
- 用布局、对齐和留白组织信息，删除无助于当前任务的标题、说明和控件。列表、详情、对话各展示所需信息，避免重复堆叠同一组数据。
- 图标使用 `lucide-preact` 与共享组件。仅图标按钮提供可访问名称、明确的悬停与键盘焦点反馈；复用公共表单、选择框、弹窗及操作菜单，保持尺寸和交互一致。

## 实现边界

- 使用当前 Preact、strict TypeScript 和已有 CSS 组织方式；Materio 是视觉参考，不意味着引入 React、MUI 或整套模板依赖。优先扩展共享组件和现有样式，避免各模块复制实现。
- 应用入口与路由归 `src/app/`，业务界面归 `src/features/`，公共控件归 `src/components/`，请求与展示辅助逻辑归 `src/lib/`。先查现有符号和调用方，再决定新增组件或抽取公共能力。
- API 通过 `src/lib/api.ts` 调用；跨端契约复用 `@abridge/protocol` 的类型和 schema，输入在边界校验，不在前端另建一套消息或状态契约。
- 身份校验和首次加载在入口统一处理，复用会话逻辑和加载界面。身份尚未确定时保持加载态，不先渲染登录表单再切换后台；身份变化及时清理旧用户的数据和临时状态。
- 异步请求处理卸载、目标切换和旧响应覆盖；表单与写操作防止重复提交，失败显示可操作的反馈。不要用加载动画掩盖错误或把请求完成当作任务成功。

## 设备与任务对话

- 设备类型、操作系统和浏览器平台由真实上报信息决定，复用设备元数据辅助函数。未知平台显示未知或通用图标，不能把所有电脑标为 macOS、所有浏览器标为 Chrome。
- 从设备进入对话后固定当前设备，并清楚展示目标。消息、历史与任务状态必须属于该设备；界面更新不能静默切换执行对象或混入其他设备记录。
- 状态、步骤数量、耗时和执行结果来自真实任务与事件。区分排队、执行、完成、失败与取消，连接在线不能代替任务成功；不编造进度、步骤或完成文案。
- 执行时间线默认折叠，展开后按实际事件展示步骤摘要及工具输入、输出；有返回截图或缩略图时提供可查看的图像，没有时不生成占位成果。
- 优先复用任务事件整理与标签逻辑。对话正文概括结果，时间线承载过程，避免在多处重复完整详情；原始输入输出按需展开，保留诊断所需信息。

## 验证与交付

- 根据改动验证真实路径：后台登录与刷新、导航切换、空态与失败态、实际平台展示；涉及对话时检查设备范围、状态更新及时间线展开。验证入口身份加载时确认没有登录页闪现。
- 视觉改动检查真实页面或截图的布局、标题栏、图标按钮和焦点行为。模拟数据或协议测试只能证明相应逻辑，交付时说明真实设备及任务执行是否验收。
- 执行适当的格式、类型和回归检查，交付前按根目录要求完成 `npm run check`。多人协作时由主 Agent 协调完整构建，避免并发构建互相覆盖产物；只说明已实际执行的验证结果。
