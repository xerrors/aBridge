安装与修复 aBridge

运行时

App 使用安装时复制到用户目录的 Node.js、已构建 CLI 和官方 Cua SDK。菜单中的“重新检查运行环境”只读取状态，不下载或替换依赖。

缺少运行文件时，退出 App，在完整源码目录使用 Node.js 26.7–26.x、npm 和 Xcode Command Line Tools 重新安装： 

npm ci
npm run build
npm run desktop:install
open "$HOME/Applications/aBridge.app"

系统权限

在“设置 → 运行环境”查看屏幕录制和辅助功能。显示“已允许”时无需重复授权；未允许时点击“前往设置”，授权实际安装的 aBridge。

原生构建输入不变时复用已签名 App。原生代码或签名变化后，macOS 可能要求重新授权。构建与签名检查不能代替实际窗口截图、键鼠操作的验证。

连接与诊断

在管理台添加电脑设备后，将 Device Key 填入 App。已有绑定使用“重新连接”，无需重复填写 Key。凭据保存在当前用户私有目录，连接失败不会自动解除本机暂停。

菜单提供暂停/恢复、停止当前任务、本机能力开关和日志入口。环境检查区分 Node、驱动加载、系统权限和服务连接；缺失能力不会作为可用能力上报。

浏览器客户端

aBridge App 提供屏幕、键鼠、文件和 Shell。浏览器操作由独立的 aBridge for Browser 扩展直连 Server，不需要本 App 或桌面权限。

每个 Profile 中的扩展分别绑定为设备；绑定后自动重连，任务按设备选择浏览器。浏览器完全退出时扩展设备离线。
